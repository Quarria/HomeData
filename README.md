# 家常账（HomeData）

家常账是一款面向个人和家庭的小型收支记录与待办管理 Web 应用。它默认进入个人空间，允许家庭成员分别记录支出，并在得到明确授权时将费用归入家庭统计。应用同时提供固定费用周期管理、提醒、统计报表、访客分享和用户主动触发的 AI 辅助能力。

项目采用前后端同仓的 Monorepo 结构，浏览器端适配桌面和手机。当前已完成 M0—M5 的主要代码实现；M6 生产发布验收、真实 PostgreSQL 并发与备份恢复、外部服务实测仍未完成。请将“代码已实现”和“已通过生产环境验收”区分看待。

## 项目背景与设计原则

- 每位成员使用独立账号；首版账号由系统管理员线下创建和分配，不提供自助注册、微信登录或代替其他成员记账。
- 登录后默认个人空间；用户可切换到自己所属的家庭空间。
- 个人支出和家庭费用按明确归属统计。个人报表以本人付款为口径，家庭报表以家庭归属为口径。
- 当前只记录支出，不记录收入。分类使用统一标准集合，水费、电费、燃气费分别统计。
- AI 仅由用户主动触发；识别结果先作为草稿，由用户核对并确认后才写入账本。
- 家庭外访客只能通过用户创建的只读分享页访问有限的统计快照，不能进入内部账目。
- 微信推送、导出和其他未确认的外部接入不作为已交付功能。

## 已实现功能

### 账号与家庭

- 用户名和密码登录、会话管理、退出登录、首次登录强制修改密码。
- 系统管理员可创建、重置和停用账号；首个管理员通过命令行交互初始化，密码不回显。
- 用户可创建家庭，家庭管理员通过完整用户名手动添加已创建账号，并管理成员、管理权交接、离开及家庭归档／恢复。
- 个人、家庭和访客权限由服务端校验；关键管理操作写入审计记录。

### 账本与票据

- 个人和家庭支出新增、编辑、搜索、筛选、软删除、回收站恢复及审计。
- 记录消费类别、名称、数量、单位、单价、金额、日期、付款人和费用归属。
- 退款必须关联原支出；累计退款不能超过原支出金额，原支出与关联退款支持成组删除和恢复。
- 使用统一支出分类，水、电、燃气独立分类，便于比较各自趋势。
- 支持 JPEG、PNG、WebP 票据上传，单张限制 10 MiB；图片保存在私有存储中，并按授权读取。
- 支持个人空间和家庭空间的费用口径，以及混合消费的归属处理。

### 待办、固定费用与站内提醒

- 个人待办只提醒本人；家庭待办面向家庭成员。
- 待办支持创建、编辑、完成、重开、删除、截止日期和说明。
- 固定费用作为周期规则管理，支持每月／每年周期、暂停／恢复、生成期次、确认付款或跳过；确认付款后才记入账本。
- 提醒设置支持每日提醒时间、待办和固定费用提前天数；消息在站内查看并标记已读。
- 提醒由 worker 扫描并持久化，避免只依赖浏览器保持打开。

### 报表、访客分享与 AI

- 报表提供日、月、年周期查询、趋势、周期比较、分类统计、退款归组、付款人排行和可筛选明细。
- 访客分享使用静态统计快照，可设置有效期和口令，并支持撤销；访客页面不展示逐笔记录或成员姓名。
- DeepSeek 适配器支持票据视觉识别和收支汇总分析。AI 默认关闭，通过服务器端环境变量配置；启用后也只在用户主动操作时调用。
- 票据识别输出待核对草稿；分析请求使用受限统计字段，不自动分享 AI 结果。
- AI 调用任务提供幂等、每日额度、失败释放和停滞任务恢复等机制。

## 当前未完成或待验收

以下事项尚不能视为生产环境已完成：

1. **正式服务器部署验收**：项目已有 Docker Compose、前后端镜像构建文件和 PostgreSQL 服务定义，但尚未在目标云服务器完成构建、部署和端到端验证。
2. **HTTPS 与域名**：首阶段可使用公网 IP 和 HTTP 访问；HTTP 流量未加密，后续如使用域名或录入真实账目，应配置 HTTPS 入口、证书签发和续期。
3. **备份与恢复**：尚未完成数据库、票据文件和必要密钥的异地备份及恢复演练，也没有已验证的回滚流程。
4. **标准 PostgreSQL 验收**：现有测试使用 PGlite；PostgreSQL 18 下的并发退款、并发付款、多 worker 提醒锁和长时间积压恢复仍待验证。
5. **真实 AI 服务验收**：AI 代码和模拟服务测试已接入；需配置 DeepSeek API Key 后，再用真实票据样本验证识别准确率、费用和数据处理要求。默认 `AI_PROVIDER=disabled`。
6. **微信推送**：尚未选择或接入具体微信推送渠道；当前提供站内提醒。
7. **移动端及完整流程最终验收**：桌面和手机的受控浏览器用例已通过，但登录、API、worker、数据库、上传、提醒和报表的完整生产链路仍需在目标环境验收。

当前首版范围内暂不提供收入记录、微信登录、导出功能和自动注册。它们属于已确认的产品取舍或暂缓项，不代表遗漏了对应的生产接入。

## 本地开发

### 环境要求

- Node.js 24 或更高版本
- pnpm 11 或更高版本

本地开发默认通过 PGlite 启动 PostgreSQL 兼容数据库，不需要单独安装 PostgreSQL 或 Docker。首次运行需联网安装依赖。

```bash
pnpm install
pnpm dev
```

开发服务器默认地址：

- Web：<http://localhost:5173>
- API：<http://localhost:3000/api/v1>
- API 存活检查：<http://localhost:3000/api/v1/health/live>
- API 就绪检查：<http://localhost:3000/api/v1/health/ready>

首次启动开发服务后，在另一个交互式终端运行 `pnpm bootstrap-admin`，按提示设置 `admin` 初始密码。此命令不会回显密码；首次登录后需修改密码。开发数据库保存在 `data/local-postgres/`，该目录不会提交到 Git。

常用检查命令：

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm test:integration
pnpm test:e2e
pnpm build
```

## 部署概览

生产环境使用 PostgreSQL，不使用 PGlite。仓库内 `deploy/compose.yaml` 定义了数据库、一次性迁移、API、worker 和 Web 服务。首次部署前，分别复制 `deploy/env.example` 为 `deploy/.env`、复制 `deploy/runtime.env.example` 为 `deploy/runtime.env`，填写公网 IP 来源、数据库凭证、会话密钥和加密密钥；数据库管理员密码与应用运行配置分开保存，AI 默认关闭。当前可通过 HTTP 按 IP 访问，登录 Cookie 会兼容 HTTP。默认 HTTP 端口为 80，持久化目录为 `/home/docker/postgres` 和 `/home/docker/homedata/receipts`。

示意流程：

```text
浏览器 / 手机浏览器
          │ HTTP + 公网 IP（首阶段）
          ▼
     Nginx / Web ─────► API ─────► PostgreSQL
                          │
                          ├────────► 私有票据存储
                          └────────► Worker（提醒、AI后台任务）
```

当前 Compose 启动会在服务器构建镜像，`HTTP_PORT` 默认映射为 `80`，浏览器可直接通过 `http://服务器IP` 访问。Docker 与 containerd 的运行数据也可配置到 `/home/docker`。HTTP 不加密账号密码和会话信息，仅适合受限的初始访问；建议限制防火墙来源，并避免在未加密连接中录入敏感账目信息。服务器资源较小时，可在本地或 CI 构建镜像后再部署。详细步骤、环境变量、数据库模型、接口和验收清单见[开发技术文档](docs/家常账-开发技术文档.md)；服务器上各服务的启停命令见[部署运维指南](docs/部署运维指南.md)。

## 安全提示

- 不要提交 `deploy/.env`、真实数据库凭证、AI API Key、会话密钥、加密密钥、用户票据或数据库目录。
- `deploy/env.example` 仅包含占位值，部署时需生成并妥善保管真实密钥。
- HTTP 按公网 IP 访问时，账号密码和会话信息会以明文传输；应限制防火墙来源，避免录入真实敏感账目，并尽早配置 HTTPS。
- 对外开放前应配置防火墙和异地备份，并验证恢复流程。
