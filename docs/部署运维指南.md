# 家常账部署运维指南

本文用于在 Ubuntu 云服务器上手动查看、启动、停止和重启家常账服务。应用由 Docker Compose 管理；命令需要在服务器 SSH 会话中执行。

## 进入部署目录

以下以当前部署目录为例。如果服务器上的目录不同，把路径替换成实际包含 `compose.yaml`、`.env` 和 `runtime.env` 的 `deploy` 目录。

```bash
cd /home/homedata/app/current/deploy
```

服务器上的 `.env` 和 `runtime.env` 保存真实凭证，不应复制到代码仓库或发到聊天中。下面命令使用 `--env-file .env`，以读取 Compose 配置；应用容器会从 `runtime.env` 读取运行配置。

## 查看状态和日志

```bash
# 查看所有服务状态
docker compose --env-file .env ps -a

# 查看所有服务最近日志
docker compose --env-file .env logs --tail=100

# 持续查看某个服务日志，按 Ctrl+C 退出日志查看
docker compose --env-file .env logs -f --tail=100 api
```

可将最后一条命令中的 `api` 换成 `db`、`worker` 或 `web`。

## 启动和停止全部服务

```bash
# 启动数据库、迁移任务、API、worker 和 Web
docker compose --env-file .env up -d

# 停止所有正在运行的服务，保留容器和持久化数据
docker compose --env-file .env stop

# 启动已经创建但已停止的所有服务
docker compose --env-file .env start
```

首次部署或发布新版本时使用 `up -d`；短暂停机后恢复可用 `start`。`stop` 不删除数据库或票据数据。

## 单个服务启停

```bash
# 启动某个服务，并确保它依赖的服务也满足启动条件
docker compose --env-file .env up -d db
docker compose --env-file .env up -d api
docker compose --env-file .env up -d worker
docker compose --env-file .env up -d web

# 停止某个服务
docker compose --env-file .env stop web
docker compose --env-file .env stop worker
docker compose --env-file .env stop api
docker compose --env-file .env stop db

# 重启某个服务
docker compose --env-file .env restart web
docker compose --env-file .env restart worker
docker compose --env-file .env restart api
docker compose --env-file .env restart db
```

正常使用时应保持 `db`、`api`、`worker` 和 `web` 运行。停止数据库会使 API 和 worker 暂时无法读写数据；只维护某个前端或后台服务时，不需要停止数据库。

## 数据库迁移任务

`migrate` 是一次性任务，执行数据库结构迁移后会正常退出，所以在状态列表里显示 `Exited (0)` 是预期行为，不需要长期运行或单独停止。

```bash
# 手动执行已提交的 Prisma 数据库迁移
docker compose --env-file .env run --rm migrate
```

通常部署新版本时，`docker compose --env-file .env up -d` 会根据依赖关系先等待数据库健康、成功执行迁移，再启动 API 和 worker。只有排查或重新执行迁移时才需要手动运行上面的命令。

## 更新代码并重新部署

当前 Compose 在服务器上根据源代码构建 `web`、`api` 和 `worker` 镜像。服务器不需要安装 Git：从本地把 `dev` 分支打包上传，服务器解包后重新构建即可。以下本地命令在 Windows PowerShell 的项目根目录执行；把 `你的服务器公网IP` 替换为实际地址。

```powershell
# 更新本地 dev 分支
git switch dev
git pull --ff-only origin dev

# 只打包已提交的代码，不包含被 Git 忽略的环境文件和依赖目录
git archive --format=tar.gz --output=homedata-release.tar.gz HEAD

# 上传到服务器
scp .\homedata-release.tar.gz root@你的服务器公网IP:/home/homedata/app/
```

然后在服务器 SSH 终端执行：

```bash
# 覆盖更新当前代码目录；不要删除 deploy/.env 或 deploy/runtime.env
cd /home/homedata/app/current
tar -xzf /home/homedata/app/homedata-release.tar.gz

# 构建更新后的镜像并启动服务
cd /home/homedata/app/current/deploy
docker compose --env-file .env up -d --build

# 检查服务状态和最近日志
docker compose --env-file .env ps -a
docker compose --env-file .env logs --tail=100 api worker web
```

每次更新都会运行一次 `migrate` 检查。Prisma 只会应用数据库中尚未执行的迁移；纯代码更新没有新迁移时不会改变数据库结构或数据。只有新增数据库迁移时，部署才会实际变更结构。此类发布前应先备份数据库；API 和 worker 会等待迁移成功后启动。

代码包只含当前分支已提交的文件。解压会覆盖同名文件，但不会删除旧版本中已经移除的文件；若发布包含删除或重命名的源码文件，应在干净的版本目录中构建，避免旧文件残留。数据库和票据数据位于 `/home/docker` 持久化目录，不随代码包更新。

## 重启 Docker 服务

只有 Docker 守护进程本身异常时才使用系统服务命令；这会影响服务器上的所有 Docker 容器。

```bash
sudo systemctl status docker
sudo systemctl restart docker
```

Docker 恢复后检查应用：

```bash
cd /home/homedata/app/current/deploy
docker compose --env-file .env ps -a
```

## 访问入口

默认 Web 端口映射为服务器 TCP 80，配置了云厂商安全组允许访问后，通过 `http://服务器公网IP` 打开。若 `.env` 中将 `HTTP_PORT` 改为其他端口，访问地址也需要包含该端口。
