# 家庭费用与待办软件需求设计

版本：1.2（已确认）
日期：2026-10-14  
阶段：技术路线设计  
状态：Q01—Q48、R01—R04 及第一版 UI 与交互原型已确认；技术路线建议稿讨论中，正式开发未开始。

## 1. 产品目标与第一版范围

通过电脑和手机浏览器记录个人及家庭日常消费，管理待办与周期费用，提供日、月、年统计及可授权分享的报表。票据识别减少手动填写，AI 分析由用户主动生成。

### 1.1 纳入第一版

- 系统管理员创建账号、线下分配；用户名与密码登录。
- 多个家庭独立使用、数据隔离；每账号最多加入一个家庭。
- 个人与家庭支出记录、数量与金额、原记录关联退款。
- 全系统统一分类，水费、电费、燃气费分别统计。
- 个人待办、家庭待办、每月和每年固定费用。
- 站内消息，微信作为首选推送渠道。
- 日月年统计、分类和成员付款报表、同期比较及明细核对。
- 只读汇总报表快照分享。
- 主动触发票据识别、分类推荐、支出分析。
- 手机适配 Web，联网保存，失败保留当前输入供重试并防止重复提交。

### 1.2 暂不纳入第一版

收入及结余、数据导入导出、自助注册、邀请链接、文字或语音记账、独立手机 App、离线记账、银行账单同步、多币种、预算、比例分摊、成员欠款结算、每周及自定义费用周期、付费购买 AI 额度、永久账号注销及永久家庭删除。

微信登录不属于当前已确认的首版范围。微信提醒与微信登录分别处理。

## 2. 账号、角色与家庭

### 2.1 账号规则

1. 系统管理员创建账号并线下分配用户名和初始密码，不开放自行注册。
2. 用户名唯一、创建后不可修改；昵称可以修改。
3. 初始密码首次登录必须修改；忘记密码由系统管理员重置。
4. 管理员不能查看用户当前密码。密码重置后已有登录立即失效，下次登录必须改密。
5. 系统管理员可停用、恢复账号；停用立即使已有登录失效，禁止登录并停止提醒，历史账目保留。
6. 无家庭时可正常使用个人功能；家庭页展示创建或等待管理员添加的状态。
7. 始终保留至少一名可登录的系统管理员。
8. 首个系统管理员由用户指定。首个系统管理员用户名为 admin，确认解释见第 11 节，不将 admin 作为所有用户的通用账号或默认密码。

### 2.2 家庭规则

1. 家庭创建者成为该家庭管理员。
2. 家庭管理员通过完整用户名添加已创建账号，不可浏览全部账号列表。
3. 账号已有家庭时不能同时加入另一家庭；家庭之间数据隔离。
4. 家庭管理员管理成员与家庭共享设置，不因此获得成员个人数据访问权。
5. 管理权可转交给现有成员，管理员退出前必须交接。
6. 家庭只剩管理员一人时，保留账号和成员身份，可归档家庭，不允许退出留下无人管理家庭。
7. 家庭管理员账号须先交接再停用；最后一位管理员无法满足交接条件时不得停用。

### 2.3 成员离开与历史记录

- 退出或被移除后，立即失去家庭整体访问权，停止接收该家庭提醒。
- 已计入家庭的账目保留，不因成员离开减少历史统计。
- 个人账本仍可只读查看本人支付的历史家庭费用和关联凭证，不可查看其他成员数据，不可修改、删除或恢复原家庭记录。
- 未完成家庭待办及固定费用管理权交给家庭管理员；此交接不改变账目付款人，不授予修改他人账目的权限。
- 不可再查看原家庭的 AI 分析历史；本人付款历史仍保留。
- 已失去权限的分享链接立即失效，不因日后重新加入而自动恢复。

### 2.4 家庭归档

- 管理员可归档、恢复家庭，不提供永久删除。
- 归档后只读历史，停止家庭提醒、撤销相关分享链接。
- 冻结所有家庭数据写入，包括新增、修改、删除、退款、恢复账目、完成或重开待办、周期配置和成员增减；仅允许管理员恢复家庭。
- 个人功能继续可用，但不能通过个人入口修改归档家庭的记录。
- 归档不能使已过期分享重新可访问，也不能自动延长已确认的记录恢复期或临时数据保留期。
- 恢复后周期费用的起点与停用成员的任务交接补充规则见第 11 节。

## 3. 导航与页面结构

手机 Web 使用底部导航，电脑网页使用相同项目的侧边导航。

| 一级页签 | 内容 | 主要子页或操作 |
| --- | --- | --- |
| 首页 | 快捷记录、近期需处理、本月开支摘要 | 记一笔、拍票据、新建待办；最多 3 项事项；查看报表 |
| 账本 | 支出与退款明细、搜索筛选 | 手动记账、票据识别核对、记录详情、凭证、已删除记录 |
| 待办与提醒 | 待办任务和固定费用 | “待办任务｜固定费用”二级切换、任务详情、周期配置、每期处理 |
| 报表 | 日月年概览、趋势、分类、成员付款和同期比较 | 图表对应明细、生成支出分析、分析历史、分享 |
| 我的 | 账号、家庭、通知、分享管理与管理员功能 | 改密、成员管理、交接、归档、按角色显示账号／分类／额度管理 |

默认进入个人空间，不默认家庭。前四项顶部提供“个人／家庭”切换，页签间沿用当前选择；新建操作默认沿用当前空间，明确展示归属并允许选择。无家庭时不产生可用的家庭操作入口。

全局“＋”提供手动记账、拍照或上传票据、新建待办；AI 分析在报表中通过独立按钮触发。

首页职责已调整为日常入口，不复制完整功能页。仅保留三块：快捷记录、近期需处理、本月开支摘要。近期事项将逾期、今天到期和近期缴费集中展示，最多 3 项，点击进入对应详情；无事项时显示完成状态。本月摘要仅显示净支出及查看报表入口。不在首页展示完整趋势图、分类排行、水电燃气趋势或最近账单列表。详细查询留在账本，完整任务与费用管理留在待办与提醒，统计分析留在报表。不再采用此前 A／B／C 首页布局选择。

### 3.1 已确认的体验优化

- 普通记账首屏优先金额、分类和条目名称；日期默认今天，数量、单位、单价、备注和凭证放入补充信息。费用归属与可见范围始终展示，不隐藏在补充信息中。
- 保存新记录后提供再记一笔及短暂撤销；撤销即时移出统计，沿用 30 天恢复规则。连续记账可沿用前一笔已明确选择的分类、归属，但不得隐藏可见性提示。保存记录本身不自动切换当前空间。
- 个人报表明确标注“本人支付，含家庭费用”，避免将本人付款误读为全部私有。记录分别标示个人费用、家庭费用；保存前说明仅本人或家庭成员可见，以及是否进入家庭统计。
- 票据核对围绕一次消费组织，先看日期、总额和分类汇总，展开商品明细，支持批量归属后单项调整。多条支出在账本成组展示，但底层记录仍分别归属、分别统计，退款继续关联具体原记录。分组金额仅汇总当前用户和筛选条件下可见的条目，不泄露其他归属的明细或金额。
- 票据提供新建记录、补充已有本人记录凭证两条路径；补充凭证不新增支出，不覆盖原金额；需核对属于同一次消费，保留混合票据原图隐私规则。
- 家庭事项显示完成者、费用显示付款人，记录保留简短操作历史；不增加评论、聊天或审批功能，不改变本人修改账目权限。
- AI 分析按“变化、依据、待核对”组织。差额和对照期间由软件计算，AI 解释汇总；可跳转核对明细，数据不足时不推断原因。保留主动触发、私有结果、汇总白名单和不自动改账的限制。
- 不增加水费、电费、燃气费专用输入或计费周期输入。三类仍使用通用数量、单位字段，继续分别统计金额趋势；实际用量可自行填写，但不强制，不推出额外用量分析模块。

访客进入独立分享页面，不显示完整应用导航；展示统计范围、快照时间和有效期，失效时显示失效提示。

## 4. 支出、退款与统一分类

### 4.1 记录字段

| 字段 | 规则 |
| --- | --- |
| 条目名称 | 消费项目名称，例如蔬菜、房租 |
| 消费分类 | 从全系统统一分类选择 |
| 日期 | 实际发生日期，可补记；统计按北京时间 |
| 金额 | 必填、两位小数，普通支出大于零 |
| 数量、单位 | 可选通用字段，例如 3 斤、2 件、度、立方米；水电燃气不提供单独专用输入 |
| 单价 | 可选，结合数量计算金额；可人工修正总额处理折扣和抹零 |
| 付款人 | 当前记账账号，不可选其他成员，不允许代记 |
| 归属 | 个人或当前家庭 |
| 备注 | 可选 |
| 凭证 | 可选，访问与清理按票据规则 |

每笔支出只保存一份，不通过复制形成家庭账。一张订单含个人与家庭费用时，拆成多笔记录，每笔只有一个归属。

### 4.2 权限与统计归属

- 个人记录仅本人查看和管理。
- 家庭记录全体当前成员可查看，仅记账本人可修改、删除和恢复；归档、离开、停用等限制优先适用。
- 管理员不能代改其他成员账目。
- 个人账本和报表默认统计本人支付的全部费用，可筛选“全部／个人归属／家庭归属”。
- 家庭账本和报表只统计家庭归属费用，两种视角存在重叠，不相加作为总支出。
- 例：个人用品 50 元、家庭用品 150 元，个人默认 200 元，个人归属筛选 50 元，家庭报表 150 元。

### 4.3 退款

1. 创建退款必须先选择一笔原支出记录，再填写退款金额和实际发生日期。
2. 一张票据有多笔支出时，选择其中对应的一笔，不直接对整张图片生成退款。
3. 退款归属、分类和付款人跟随原支出，不作为收入。
4. 可多次部分退款，金额大于零，累计不超过原支出；修改原支出金额不能低于累计退款。
5. 退款按实际退款日所在周期抵减支出，不回写原支付日的发生金额。
6. 退款管理沿用原记录本人权限与金额校验；删除原支出时关联退款一起移出统计，恢复时一起恢复。
7. 原家庭记录在离开或归档后不可新增退款，需先满足对应访问和写入权限。

### 4.4 分类

统一分类：餐饮、日用、住房、水费、电费、燃气费、交通、医疗、教育、娱乐、服饰、通讯、其他。

水电燃气不另设专用表单，继续使用通用数量、单位。

水费、电费、燃气费分别展示金额及趋势，不合并。仅系统管理员可新增、改名和停用分类，家庭管理员与成员只能选择。已使用分类不直接删除；停用后不用于新记录，历史账目与报表继续可查。

### 4.5 删除、恢复与凭证清理

- 删除立即移出统计，并提示对个人和家庭统计的影响。
- 30 天内可恢复，重新计入统计；仅记账本人可恢复，且家庭记录须仍有对应家庭写入权限。
- 30 天后清理记录；归档不会延长恢复期。
- 共用图片仍被其他记录引用时保留；最后一笔关联记录恢复期满后才清理原图。
- 删除单张凭证不等于删除消费记录；不得连带删除其他记录仍在使用的图片。

## 5. 待办与固定费用

### 5.1 普通待办

包含标题、说明、截止日期、个人／家庭归属、可选负责人、状态。

- 首版只设置截止日期，不设置精确时刻；当天结束后，未完成事项算逾期。
- 个人任务只提醒本人；家庭任务提醒全体当前成员，负责人不改变提醒范围。
- 一名成员完成家庭任务即整体完成，全家可见完成状态。
- 创建者可编辑、删除或重新打开；创建者离开时未完成家庭任务由管理员接管。
- 完成后停止提醒；重开按截止日期恢复，逾期从下一次提醒开始，不立即重复推送。
- 修改截止日期后使用新日期计算后续提醒，已发消息保留处理历史，不把过期提醒当作当前任务状态。

### 5.2 固定费用配置

配置名称、个人／家庭归属、每月／每年周期、首次到期日期、可选预计金额、提醒设置及启用状态。

- 预计金额可空，例如水费；支付时必填实际金额。
- 不存在的日期回落至当月最后一天；年周期 2 月 29 日在平年使用 2 月 28 日。
- 本期事项在首次提前提醒时生成，确认支付前不记账。
- 创建者可调整周期、暂停或恢复，周期修改只影响未来未生成事项。
- 暂停后不生成新事项，已有事项仍需完成或跳过。
- 恢复不补暂停期事项，从下一期继续。
- 创建者可跳过本期，不生成支出；离开后的管理人接续相同配置权限。

### 5.3 本期支付与撤销

- 家庭成员可确认家庭固定费用付款，确认人就是付款人，不允许代记。
- 确认实际金额后生成一笔关联支出，本期变为已支付，全家停止本期提醒。
- 同期仅允许一筆有效付款，重复点击或同时确认不重复记账。
- 改金额直接编辑关联支出；原付款人删除误记支出后，本期重新待处理。
- 恢复该支出后本期重新已支付；若已有新付款，禁止恢复旧付款。
- 已支付事项不可像普通待办直接重开，须联动付款记录，保证账目和状态一致。
- 全额退款不自动认定该期费用需要再次付款；退款表示付款后的返还，不等于撤销误记。

## 6. 提醒规则

| 事项 | 默认提醒 |
| --- | --- |
| 固定费用 | 提前 3 天及到期当天 |
| 普通待办 | 提前 1 天及到期当天 |
| 逾期未处理 | 每天一次 |
| 已完成、已支付、已跳过 | 停止本期提醒 |

默认北京时间上午 9 点，允许调整提醒时间及频率；调整不能将家庭事项的提醒对象默认缩减为负责人。

- 站内保留消息，微信为首选外部推送渠道。
- 同一成员同一提醒时间的多项事项合并摘要，家庭事项分别通知所有当前成员。
- 新成员从加入后开始接收有效提醒，不补发加入前的历史消息。
- 停用账号不接收提醒；归档家庭不产生家庭提醒。
- 微信未绑定、不可用或发送失败明确提示，不显示成功。
- 失败有限重试并去重；具体次数与间隔在技术实现中确定，但不能重复形成业务消息。
- 系统漏发时只补当前有效提醒，不连续补发历史消息；实际漏生成的活动期事项不得当作“暂停期”自动丢弃。
- 微信服务受理成功与用户已读是不同状态，不把受理当作已读。

微信接入方式、账号资质、授权条件及通道允许的提醒频率需在技术路径阶段核验。当前确认的是微信作为首选需求和站内兜底行为，不承诺尚未核验的通道一定满足每日推送。

## 7. 报表与统计口径

### 7.1 统计规则

- 人民币、北京时间，按自然日、月、年统计。
- 同时展示原始支出、退款、净支出；净支出＝支出－退款。
- 趋势与分类默认净支出，可以切换原始支出；明细合计须与报表一致。
- 发生日期决定所属周期，补记或编辑后重算相关统计。
- 删除记录不计入，恢复后重计；成员离开不删除家庭账目。
- 跨月退款可能使某期或某分类净支出为负，不截断为零，用支持负值的条形图展示，不强行转换为占比环形图。
- 未结束周期与上期相同进度比较，避免将半月与整月比较；没有对应日期时按对照周期实际日历边界处理。
- 无数据展示空状态；比较期金额为零不显示增长百分比。
- 成员付款统计表示谁支付了费用，不等于谁消费、谁欠款。

### 7.2 报表内容

| 报表 | 用途 |
| --- | --- |
| 概览 | 原始支出、退款、净支出 |
| 趋势 | 日月年支出变化 |
| 分类汇总与排行 | 分类金额及变化，水电燃气独立趋势 |

## 8. AI 功能

### 8.1 主动触发原则

拍照识别、分类推荐、支出分析均需用户主动操作。打开页面、编辑记录或定时任务不自动调用 AI。用户主动启动票据识别时可同时完成分类推荐。

### 8.2 票据识别

流程：拍照／上传 → 主动识别 → 核对草稿 → 确定各条归属 → 正式保存。

- 目标是减少消费类型、金额、数量等内容的手动填写，不构建报销或票据审批功能。
- 每次一张 JPG、PNG、WebP，最多 10 MB；不符合时提示更换。
- 识别日期、条目、数量、金额并推荐统一分类；缺失或不确定字段明确标记。
- 核对前不计入报表；可修改字段、删除误识别条目并手动补充。
- 票据总额与明细合计不符时修正或确认实际金额，不自动改账；正式金额以确认后的记录为准，不将票据总额再次累计。
- 疑似重复票据提示本人，可确认继续，防重复提交仍独立生效。
- 识别失败允许重试或手动记账，不阻断主流程。

### 8.3 图片、草稿与隐私

- 接受图片上传至外部 AI 服务识别，上传前说明处理方式。
- 草稿和临时图片仅本人可见，保留 7 天，过期清理。
- 正式保存时选择是否保留凭证；已正式保留图片不随草稿到期删除。
- 个人票据本人可见；纯家庭票据当前成员可见。
- 混合票据同时含个人和家庭消费时，原图始终仅本人可见，家庭成员仅看到家庭条目。
- 离开后本人仍可看本人历史记录凭证；共用原图按最后关联记录恢复期清理。

### 8.4 支出分析

- 报表中点击“生成支出分析”，使用当前空间和当前时间范围。
- 仅发送支出、退款、净支出、分类金额和时间趋势等统计字段；不发送收入、成员姓名、用户名、备注、商家或条目文本、票据图片。
- 结果发起人私有，显示范围和生成时间；不得修改账目、自动刷新或自动进入访客分享。
- 成功结果保存在本人分析历史，可删除；查看不计次，重生成需再点击并计次。
- 成员离开后原家庭分析不再可查看；本人费用记录仍可看。

### 8.5 额度

| 调用 | 默认每日上限与计次 |
| --- | --- |
| 票据识别 | 每账号 20 次，附带分类合计一次 |
| 单独分类推荐 | 消耗一次识别额度 |
| 支出分析 | 每账号 5 次，成功生成计一次 |
| 调用失败 | 不扣业务额度 |
| 查看草稿、已有分析 | 不调用 AI，不扣额度 |

系统管理员可分别调整上限，北京时间零点重置。超额提示，手动记账和普通报表仍可用；不提供购买额度。

## 9. 访客分享

1. 个人报表本人可分享；家庭报表仅家庭管理员可分享。
2. 第一版只分享汇总固定快照，不含逐笔明细、成员姓名、备注、票据或 AI 分析。
3. 明确标示统计范围和快照生成时间，后续记账不自动更新快照。
4. 有效期 1、7、30 天，默认 7 天；可提前撤销、可设访问口令，不提供永久链接。
5. 归档家庭、分享者离开、停用或交接后失去相应权限，相关链接立即失效。
6. 恢复家庭、账号或权限不自动恢复旧链接。
7. 失效快照保留 30 天供有相应权限的分享管理查看，然后清理；访客自失效起不可访问。
8. 访客只能读取授权汇总，不能修改、创建任务或接收家庭提醒。
