# HomeData 服务器部署手册

本文只记录经过验证的标准部署步骤、必要约束和已知故障处理，不记录每次部署流水。部署前先读取本文。目标是将 GitHub 仓库 `Quarria/HomeData` 的 `origin/dev` 已提交代码发布到 Ubuntu 服务器；服务器不需要安装 Git。

## 固定环境与安全约束

- 本机 SSH 已配置持久别名 `homedata-server` 和免密码密钥。部署时直接用该别名，不向用户索取服务器地址、密码，不要求用户切换终端输入密码。不要将服务器地址、私钥路径、公钥、凭证写入本文或仓库。
- 源码目录：`/home/homedata/app/current`；Compose 目录：`/home/homedata/app/current/deploy`；Compose 项目：`homedata`。
- PostgreSQL 持久数据：`/home/docker/postgres`；票据数据：`/home/docker/homedata/receipts`。
- 服务器 `deploy/.env` 和 `deploy/runtime.env` 含真实凭证。只检查文件存在；不要输出、覆盖、下载或提交这些文件。
- 不要重启服务器或 Docker 守护进程来处理部署卡顿。严禁 `docker compose down -v`、删除持久化目录、重置生产数据库。
- API、Web 必须分开构建且严格串行。不要使用 `docker compose up -d --build` 或 `docker compose --parallel 1 build`：曾导致低内存服务器同时构建并 OOM。

## 1. 确认代码和 SSH

在 Windows PowerShell 仓库根目录运行。只发布已经推送到 `origin/dev` 的提交，不打包本地未提交或未跟踪文件。

```powershell
git fetch origin
if ($LASTEXITCODE -ne 0) { throw '无法刷新 origin；停止部署，不要部署过期引用' }
git status --short
ssh.exe -o BatchMode=yes homedata-server "printf 'SSH_OK '; hostname"
if ($LASTEXITCODE -ne 0) { throw 'SSH 免密连接失败；检查本机 SSH 配置和网络，不要切换密码登录或要求用户重启' }
```

SSH 或 SCP 始终使用 `homedata-server` 别名。部署时通过 `git archive origin/dev` 打包，避免误带本地文件。若仓库工作区未提交内容，只提示用户并继续以已推送的 `origin/dev` 为准。

## 2. 检查服务器和数据库迁移

确认 Docker 正常、磁盘空间足够、Compose 文件和两个环境文件存在；不得打印环境文件内容。数据库及票据必须仍使用上述持久化路径。

```powershell
ssh.exe homedata-server 'set -e; test -f /home/homedata/app/current/deploy/compose.yaml; test -f /home/homedata/app/current/deploy/.env; test -f /home/homedata/app/current/deploy/runtime.env; docker info >/dev/null; df -h /'
```

对比目标版本和服务器当前源码中的 Prisma 迁移目录：目标新增迁移时，先按项目流程备份数据库再继续；目标删除已有迁移时停止部署并查明原因。

```powershell
$target = @(git ls-tree -r --name-only origin/dev -- apps/server/prisma/migrations | Where-Object { $_ -match '/migration\.sql$' } | ForEach-Object { ($_ -split '/')[-2] } | Sort-Object -Unique)
if ($LASTEXITCODE -ne 0) { throw '读取目标迁移列表失败' }
$server = @(ssh.exe homedata-server "find /home/homedata/app/current/apps/server/prisma/migrations -mindepth 2 -maxdepth 2 -type f -name migration.sql -printf '%h\n' | sed 's#.*/##' | sort")
if ($LASTEXITCODE -ne 0) { throw '读取服务器迁移列表失败' }
$added = @($target | Where-Object { $_ -notin $server })
$removed = @($server | Where-Object { $_ -notin $target })
if ($removed.Count) { throw "目标版本删除了已有迁移：$($removed -join ', ')；停止部署" }
if ($added.Count) { Write-Host "先备份数据库，再部署新增迁移：$($added -join ', ')" }
```

## 3. 打包、上传和解包

```powershell
$releaseId = (git rev-parse --short=12 origin/dev).Trim()
if ($releaseId -notmatch '^[0-9a-f]{12}$') { throw '无法确认 origin/dev 提交 ID' }
$archive = Join-Path $env:TEMP "homedata-release-$releaseId.tar.gz"
git archive --format=tar.gz --output=$archive origin/dev
if ($LASTEXITCODE -ne 0) { throw '打包失败' }
scp.exe $archive "homedata-server:/home/homedata/app/homedata-release-$releaseId.tar.gz"
if ($LASTEXITCODE -ne 0) { throw '上传失败；停止部署' }
$remoteArchive = "/home/homedata/app/homedata-release-$releaseId.tar.gz"
$remoteCommand = "set -e; test -f /home/homedata/app/current/deploy/compose.yaml; test -f /home/homedata/app/current/deploy/.env; test -f /home/homedata/app/current/deploy/runtime.env; docker info >/dev/null; cd /home/homedata/app/current; tar -xzf '$remoteArchive'; cd deploy; docker compose --env-file .env config --quiet"
ssh.exe homedata-server $remoteCommand
if ($LASTEXITCODE -ne 0) { throw '服务器解包或 Compose 校验失败；停止部署' }
```

`git archive` 仅包含目标提交中已跟踪的文件。解包会覆盖同名源码，但不会清理已删除文件；若本次发布删除或改名了源码文件，应改用干净的版本目录构建，不能让旧文件残留进镜像。不要覆盖 `.env` 或 `runtime.env`。

## 4. 预检基础镜像

基础镜像版本固定为 Dockerfile 中记录的 digest；只有本机缺失时才拉取。Compose 构建统一加 `--pull=false`，不因检查 Docker Hub 而等待。基础镜像要升级时，先验证新 digest 并同步修改两个 Dockerfile 和本文。

```powershell
ssh.exe homedata-server 'set -e; node_image="docker.io/library/node:24-alpine@sha256:44fce696f38ba8c987c4db89954051000bbd05ffd8d8659ba15ed4a8602e937f"; nginx_image="docker.io/library/nginx:1.29-alpine@sha256:5616878291a2eed594aee8db4dade5878cf7edcb475e59193904b198d9b830de"; docker image inspect "$node_image" >/dev/null 2>&1 || docker pull "$node_image"; docker image inspect "$nginx_image" >/dev/null 2>&1 || docker pull "$nginx_image"; echo BASE_IMAGES_READY'
```

必须看到 `BASE_IMAGES_READY` 且退出码为 0。Dockerfile 不使用远程 `# syntax` 前端，避免 BuildKit 为前端额外访问 Docker Hub。

## 5. 逐个构建 API 和 Web

Dockerfile 先复制 package manifests 再复制源码，并通过 BuildKit cache mount `homedata-pnpm-store-v11` 保留 pnpm 下载包。普通源码改动可复用 install 层；依赖清单变化时只下载缺失或变化的包。首次创建缓存或更换依赖版本仍可能下载。

服务器内存有限。API 的 `pnpm build` 会递归编译 workspace；临时把 `workspaceConcurrency` 设为 1 可避免并发编译耗尽内存。以下命令还把网络并发限制为 4，并用 trap 在成功、失败或信号退出时恢复原始配置。一次只运行一个构建，必须确认 API 成功后才开始 Web。

API：

```powershell
ssh.exe homedata-server 'set -e; cd /home/homedata/app/current; backup=/tmp/homedata-pnpm-workspace.yaml.original; workspace=/home/homedata/app/current/pnpm-workspace.yaml; if test -e "$backup"; then echo DEPLOY_TEMP_BACKUP_EXISTS; exit 1; fi; cp "$workspace" "$backup"; restore_workspace() { if test -f "$backup"; then cp "$backup" "$workspace" && rm -f "$backup"; fi; }; trap restore_workspace EXIT; trap "exit 129" HUP; trap "exit 130" INT; trap "exit 143" TERM; printf "\nnetworkConcurrency: 4\nworkspaceConcurrency: 1\n" >> "$workspace"; cd /home/homedata/app/current/deploy; docker compose --env-file .env build --pull=false api; echo API_IMAGE_BUILD_OK'
```

等待命令完成，确认 `API_IMAGE_BUILD_OK` 和退出码 0。然后单独运行 Web：

```powershell
ssh.exe homedata-server 'set -e; cd /home/homedata/app/current; backup=/tmp/homedata-pnpm-workspace.yaml.original; workspace=/home/homedata/app/current/pnpm-workspace.yaml; if test -e "$backup"; then echo DEPLOY_TEMP_BACKUP_EXISTS; exit 1; fi; cp "$workspace" "$backup"; restore_workspace() { if test -f "$backup"; then cp "$backup" "$workspace" && rm -f "$backup"; fi; }; trap restore_workspace EXIT; trap "exit 129" HUP; trap "exit 130" INT; trap "exit 143" TERM; printf "\nnetworkConcurrency: 4\nworkspaceConcurrency: 1\n" >> "$workspace"; cd /home/homedata/app/current/deploy; docker compose --env-file .env build --pull=false web; echo WEB_IMAGE_BUILD_OK'
```

同样确认 `WEB_IMAGE_BUILD_OK` 和退出码 0。若构建失败，先确认临时备份不存在、`pnpm-workspace.yaml` 已恢复，再诊断；不要启动另一个并行构建或更新容器。下载有进度但较慢时继续等待，不要按 Ctrl+C、重启服务器或 Docker。

## 6. 应用、处理已知 seed 问题并验收

两个镜像都构建成功后才更新容器，不带 `--build`：

```powershell
ssh.exe homedata-server 'set -e; cd /home/homedata/app/current/deploy; docker compose --env-file .env up -d'
```

**已知问题：** 当前运行镜像可能不含 Prisma seed 所需的 `tsx`。若 `migrate` 日志先显示 `No pending migrations to apply`，随后出现 `spawn tsx ENOENT`，则迁移已无待应用项，但 seed 子步骤失败，Compose 会停止启动依赖 migrate 的应用服务。先查看迁移日志，只有确认无待执行迁移后才用下面的 Node 24 方式补跑幂等 seed；seed 成功后再启动应用服务：

```powershell
ssh.exe homedata-server 'set -e; cd /home/homedata/app/current/deploy; docker compose --env-file .env logs --no-color --tail=80 migrate'
ssh.exe homedata-server 'set -e; cd /home/homedata/app/current/deploy; docker compose --env-file .env run --rm --no-deps --entrypoint sh migrate -c "cp prisma/seed.ts dist/prisma/seed.ts && node --experimental-strip-types dist/prisma/seed.ts"; docker compose --env-file .env up -d --no-deps api worker web'
```

这只是应急恢复；该情况下 `migrate` 会显示 `Exited (1)`，不能记录为正常。代码层持久修复应让运行镜像提供 seed 运行所需依赖，再通过常规 `up -d` 验证。如迁移日志显示实际迁移失败或有待执行迁移，不要补跑 seed 或启动应用，先停止并评估数据库备份/恢复流程。

服务端验收：

```powershell
ssh.exe homedata-server 'set -e; cd /home/homedata/app/current/deploy; docker compose --env-file .env ps -a; curl --max-time 10 -fsS -o /dev/null -w "LOCAL_HTTP %{http_code}\n" http://127.0.0.1/; docker compose --env-file .env exec -T api node -e "fetch(\"http://127.0.0.1:3000/api/v1/health/ready\").then(async r=>{console.log(\"API_READY \"+r.status+\" \"+(await r.text()).slice(0,200));process.exit(r.ok?0:1)}).catch(e=>{console.error(e);process.exit(1)})"; docker inspect -f "{{.Name}} restarts={{.RestartCount}} status={{.State.Status}}" homedata-api-1 homedata-worker-1 homedata-web-1 homedata-db-1'
```

验收要求：数据库 healthy；API readiness 和本机网页 HTTP 返回 200；API、worker、web 运行且重启计数稳定为 0。再用配置好的公开域名从本机验证公网 HTTP 200（不要把服务器 IP 或域名写入本文）。如异常，查看容器状态及最近日志，不要打印环境文件或凭证。

## 7. 清理和收尾

仅在验收成功后清理 regular 构建层；它会保留 pnpm 所在的 `exec.cachemount`：

```powershell
ssh.exe homedata-server 'docker buildx prune --all --filter type=regular --force'
ssh.exe homedata-server 'docker system df; df -h /'
Remove-Item -LiteralPath $archive
ssh.exe homedata-server "rm -f -- '$remoteArchive'"
if ($LASTEXITCODE -ne 0) { Write-Warning '服务器发布包未清理；仅按本次提交 ID 删除对应文件' }
```

**禁止**无过滤器的 `docker buildx prune --all` 或 `docker builder prune --all`，它们可能删除 pnpm 下载缓存，使下次依赖安装重新下载。不要为节省空间删除镜像、数据库、容器或票据数据。验收不通过时先保留现场，不清理缓存与发布包，以便诊断。

## 故障处理速查

- PowerShell 临时脚本被 Execution Policy 拒绝、PSReadLine 历史文件访问被拒：这是本机终端问题；直接用上文的 `ssh.exe` / `scp.exe` 命令，不生成临时脚本，不要求用户手动输密码。
- SSH 输出 `close - IO is still pending on closed socket`：若命令成功标记已出现且退出码为 0，先运行验收检查实际状态，不要立刻重部署。
- 构建卡顿或服务器负载高：按串行构建确认当前命令进度；并行构建会使低内存服务器 OOM。不要重启服务器或 Docker，不要中断仍有进度的构建。
- Docker Hub 网络问题：本机已有固定 digest 时使用 `--pull=false`，无需查询或拉取；仅镜像缺失时才拉取。不要临时更改基础镜像版本或添加远程 Dockerfile frontend 来绕过网络。
- seed `tsx ENOENT`：严格按上面的日志判断和补跑步骤；“没有待执行迁移”与“seed 子步骤成功”是两个不同状态。
- 外网不可达但服务本机正常：检查云安全组和服务器防火墙的 HTTP 端口配置，不要修改数据库或重启服务器。
