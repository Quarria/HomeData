# 家常账服务器部署交接说明

本文供其他开发窗口接手部署时使用。目标是把仓库 `https://github.com/Quarria/HomeData` 的 `dev` 分支部署到现有 Ubuntu 云服务器。采用本地打包后上传的方式，服务器不需要安装 Git。

## 服务器与项目位置

- 系统：Ubuntu 26.04，Docker 和 Docker Compose 已安装。
- SSH：`root` 用户、端口 `22`、密码登录。服务器地址和密码不写入仓库；部署窗口需要服务器地址时请向用户确认，密码只在终端交互提示中输入，不放入命令、文档或聊天记录。
- 应用源码目录：`/home/homedata/app/current`。
- Compose 目录：`/home/homedata/app/current/deploy`。
- Compose 项目：`homedata`。
- PostgreSQL 数据目录：`/home/docker/postgres`。
- 票据文件目录：`/home/docker/homedata/receipts`。
- Compose 环境文件：服务器上的 `deploy/.env` 与 `deploy/runtime.env`。它们含真实配置，不得覆盖、删除、下载到本地或提交到 Git。
- 入口：HTTP 80，浏览器访问 `http://服务器公网IP`。如果外网无法访问，检查云厂商安全组 TCP 80 入站规则。

## 部署前检查

1. 从 GitHub 获取最新 `origin/dev`；只部署已提交并推送的代码。不要把本地未提交或未跟踪的设计截图、测试证据带入发布包。
2. 通过 SSH 检查服务器可登录、Docker 正常，以及目标目录下存在 `current/deploy/compose.yaml`、`.env` 和 `runtime.env`。
3. 确认数据库和票据使用上述 `/home/docker` 持久化路径。严禁运行 `docker compose down -v`、删除持久化目录或重置生产数据库。
4. 如果目标提交新增 `apps/server/prisma/migrations/` 迁移，先安排数据库备份再发布。仅改业务代码且没有新迁移时，不需要手工迁移或改数据库。

## 从本地打包并上传

在 Windows PowerShell 的仓库根目录执行。先将 `你的服务器公网IP` 替换为实际地址：

```powershell
git fetch origin
git archive --format=tar.gz --output=homedata-release.tar.gz origin/dev
scp .\homedata-release.tar.gz root@你的服务器公网IP:/home/homedata/app/
```

`git archive` 仅包含 `origin/dev` 中已提交的文件，不包含服务器环境文件、`node_modules` 或工作区未提交内容。`scp` 会交互式提示 SSH 密码。

## 在服务器更新服务

在 SSH 终端执行：

```bash
cd /home/homedata/app/current
tar -xzf /home/homedata/app/homedata-release.tar.gz

cd /home/homedata/app/current/deploy
docker compose --env-file .env config --quiet
docker compose --env-file .env up -d --build
docker compose --env-file .env ps -a
docker compose --env-file .env logs --tail=100 api worker web
```

Compose 会在服务器构建 `web`、`api` 和 `worker` 镜像。`migrate` 是依赖中的一次性任务：每次部署会检查 Prisma 迁移状态；仅当有未执行的新迁移时才变更数据库。API 和 worker 等待迁移成功后启动。`migrate` 显示 `Exited (0)` 属于正常状态。

解压会覆盖同名源码文件，但不会自动删除旧版本中已经移除的文件。如果本次变更删除或重命名了源码文件，应在干净的源码目录构建，避免残留文件进入镜像。数据库与票据数据位于独立持久化目录，不随代码包解压。

## 发布后验收

1. `docker compose --env-file .env ps -a` 中 `db`、`api`、`worker`、`web` 均处于运行状态；`migrate` 为 `Exited (0)`。
2. 检查 `api`、`worker`、`web` 最近日志，没有启动失败或迁移错误；不要把环境文件或密码内容打印到日志。
3. 在服务器本机执行 `curl -I http://127.0.0.1`，再从外网浏览器打开 `http://服务器公网IP`。
4. 验证登录、浏览账本和创建一条测试待办。真实账目不要用于部署验收测试。

## 故障处理边界

- 如果 `config --quiet` 或构建失败，先保留现场和日志，不删除数据卷。
- 如果迁移失败，不继续强行启动 API／worker；记录错误并先判断是否需要恢复数据库备份。
- 如果容器正常但外网无法访问，检查 TCP 80 安全组和服务器防火墙；不要因此修改数据库配置。
- 当前初始管理员密码、数据库密码、会话密钥、DeepSeek API Key 等均不保存在本文件或仓库中。
