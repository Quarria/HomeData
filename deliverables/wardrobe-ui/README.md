# 衣柜页面交互原型

沿用家常账生活日历视觉，供确认页面结构和操作顺序。功能范围见 [需求与实施方案](../../docs/智能衣柜-需求与实施方案.md)，展示提案见 [页面与交互方案](../../docs/智能衣柜-页面与交互方案.md)。

## 预览

在项目根目录运行 `node deliverables/wardrobe-ui/server.cjs`，打开 [衣柜原型](http://127.0.0.1:4175/)。也可以直接打开 `index.html`。

支持地址状态：

- `?state=garments`：衣物列表。
- `?state=detail`：衣物详情。
- `?state=entry`：新增衣物。
- `?state=purchase`：衣物与支出一次录入表单。
- `?state=gift`：替同家庭成员购买的表单。
- `?state=daily`：日常推荐。
- `?state=trip`：旅行输入。
- `?state=trip-result`：三日旅行结果。
- `?state=trip-partial`：部分日期暂无预报的状态。
- `?state=favorites`：收藏搭配。

## 演示边界

衣物为 SVG 轮廓占位，正式应用显示用户照片；不是抠图效果演示。天气、城市搜索、推荐和剩余次数是模拟数据，没有 API 调用或费用。原型中的日期不代表真实预报。

表单、筛选、详情、状态更新与收藏可点击，衣物和收藏使用此原型地址下的 localStorage 保存；不读取或写入正式账号和数据库。衣物识别按钮只演示未选图片提示／失败手工继续，不执行真实识别。统一购衣表单展示金额、消费日期、添置日期和收衣人；这些值仅作为模拟录入信息保存在原型本地，不创建真实账单或向其他账号实际投送。账目和待办的完整业务仍未实现。

首版原型没有完整手动新建套装、家庭成员切换、真实天气自动查询、30 天完整结果、真实 AI 限额和后端错误处理。它们的产品设计已写入页面方案，正式实现仍需按需求验收；不因页面有按钮就视为功能交付。

不展示项目开发、模型配置和假成功提示；其他模块的导航仅作为现有应用外壳，不连接正式业务。

## 视觉与交互核验

桌面 1440×900、手机 390×844 与窄屏 320×780 的截图和自动布局检查保存在 `screenshots/`。后续修正和最终结果见 `visual-review.md`。

动效为按压反馈、分段底板切换、抽屉进入和内容短淡入，支持减少动态效果。不做滚动装饰动画。

文案减法：不增加统计大卡、天气解释长文和搭配营销文案；保留衣物名、状态、可见范围、预报时间和主操作。

适用季节已改为春／夏／秋／冬四个独立复选项；可任意组合、全部选择或全部不选。保存为数组，兼容原型已有的“春秋”“四季”等旧值。多选与保存后的详情截图见 `seasons-evidence/` 和 `seasons-saved/`。
